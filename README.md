# MATCS · 音乐事件的绝对时空坐标系

> **一句话**：把「第 *m* 小节第 *t* 拍」变成全局唯一的绝对 tick，并让它在**变拍号**下依然正确。

音乐记号的位置表达是**相对**的——它的度量单位「一拍」由拍号定义。拍号一变，尺子就变了，
同一个表达式指向不同的物理时长。这个仓库给出该问题的坐标系统、闭式解、失效边界，
以及**可执行的参考实现**。

## 30 秒看懂问题

DAW 与符号音乐库里通行的换算是：

```
AbsTick = ((M − 1) · BPI + (T − 1)) · TPB        TPB = PPQ × 4 / Denom
```

它假设**全程只有一把尺子**。一旦作品中途变拍号，这个式子就错了：

| 段 | 小节 | 拍号 | BPI | Denom | TPB | 小节长 |
|---|---|---|---|---|---|---|
| 1 | 1–4 | 4/4 | 4 | 4 | 960 | **3840** |
| 2 | 5–10 | 3/4 | 3 | 4 | 960 | **2880** |
| 3 | 11–18 | 6/8 | 6 | 8 | 480 | **2880** |

在「5.1.00」（第 5 小节第 1 拍）：

```
原式（拿段 2 的 BPI 从第 1 小节硬乘）   ((5−1)·3 + 0)·960 = 11520
真实值（分段累加）                      4 × 3840         = 15360
                                        误差             = 3840  ← 恰为一个 4/4 小节
```

**这就是 DAW 里「切换拍号后音符系统性偏移」的根因。**

> 换个说法：原式以为函数是**一条直线**，实际是**一条折线**。
> 对直线，一个乘法通吃；对折线，只能**分段求和**。

11.1.00      32640      28800     3840   ✅
全部断言通过 ✅

同一脚本还复现了事件判据——**音符起始 / 连奏 / 断奏 / 休止结束四类边界由同一条件给出**：

```python
scan_events([60]*960 + [0]*480 + [67]*960 + ...)
# t= 960  60 → 0    断奏/休止开始
# t=1440   0 → 67   休止结束
# t=2400  67 → 64   连奏（音高改变）
```

## 三件事

1. **统一的符号级事件判据** —— 事件 = 纵向值发生改变的瞬间。音符起始、连奏、断奏与休止
   由此归约为同一条件；休止被重定义为**空事件**（音高为空而起止明确），时间轴上不再有未定义区间。
2. **变拍号下的闭式及其退化性质** —— 把原式推广为分段求和，并证明原式是该式在段数 *n* = 1 时的退化特例。
3. **适用域的定量刻画** —— 参数量随拍号变化密度线性增长。当密度趋近「每小节一变」时，
   参数量趋近谱面本身、公式的杠杆归零，**此时正解不是更好的公式，而是范式切换**（拍号事件表 + 二分查找）。

## ⚠️ 什么时候不要用它

- **不从音频波形推断拍号** —— 段表必须由外部提供（工程数据或乐谱标注），该假定不可回避
- **不给出取整误差的严格上界**
- **未做跨实现的交叉验证** —— 目前只有 REAPER 一种宿主
- **密集变拍号时闭式失效** —— 见上面第 3 条，该退化为事件表 + 二分查找
- **不就音乐性作任何主张**
- **本方法是计算器，不是审计员** —— 你传什么它算什么，它不校验前提

## 这个换算本身不是新的

小节—拍—tick 与绝对 tick 的换算在 DAW、符号音乐库与游戏音频引擎中已是标准做法——
Unreal 的 `FBarMap` 接口、MusPy、mido 均提供等价实现。**本仓库不主张其为新。**

真正主张的是建立在它之上的那三件事（见论文 §2.8 与 §1.4），
以及本仓库新增的**跨实现实测验证**。

## 技术栈与编译前提

XeLaTeX + `ctex` + 自建版式；Markdown 由 pandoc `gfm+attributes` 生成。

### ⚠️ 首次编译【中文版】前必须做两步

仓库**不含**字体与矢量插图（体积大 / 可再生成），二者都要先跑脚本生成本地副本：

```bash
python tools/make_static_instances.py   # ① 抽出思源宋体静态字重（约 28 MB）
python tools/make_figures.py            # ② 生成 figures/ 下 5 张矢量插图 fig-*.pdf
```

两步都跳过的话，`paper.tex` 会因为**找不到字体**或**找不到插图**而编译失败。

> **英文版（`paper.en.tex`）不受影响** —— 它走 `musepaper-en.sty`，不含任何 CJK 机制，
> 可直接 `xelatex` 编译，无需上述任何准备。

### 两处踩过的坑

- **变量字体的默认实例未必是 Regular。** `NotoSerifSC-VF.ttf` 的 `wght` 轴是
  `200 .. 200 .. 900`——**默认实例是 ExtraLight**。XeLaTeX 不支持变量轴、只取默认实例，
  于是正文一度全是极细体，而 `AutoFakeBold` 只是把极细体描粗、把问题掩盖住了。
  解法：`tools/make_static_instances.py` 抽出静态字重。
- **pandoc 的 `-t gfm` 会丢弃标题锚点**，导致所有 `\ref{sec:…}` 无法解析（实测残留 44 处）。
  必须用 `-t gfm+attributes`。

### 中英双语的 Markdown 是怎么生成的

`README.md` 与 `README.en.md` **不是手写的**，而是从各自的 `.tex` 生成：

```bash
python tools/build_github.py    <论文目录> <输出目录>     # 中文 → README.md
python tools/build_github_en.py <论文目录> <输出目录>     # 英文 → README.en.md
```

两者**共用同一条流水线**（公式归一化、自定义环境转代码块、图表自动编号与交叉引用解析），
只按语言替换输入文件名、题名块提取规则与输出标签。
术语约定见 [`tools/glossary-en.md`](tools/glossary-en.md)。
